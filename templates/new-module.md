# 新业务模块准入模板

新模块进入 MC Plan 前必须回答：

1. 用户问题、成功标准和首个纵向链路是什么？
2. 模块拥有和明确不拥有哪些数据？
3. 能否在不连接 Core/Community 的情况下完成其声明的独立功能？
4. 接入官方生态需要哪些 OIDC scope、API、事件和 SDK？
5. 是否需要新增 Resource type；其元数据 Schema 与版本策略是什么？
6. 生成或处理成本如何计量、限额和审计？
7. 隐私、许可、内容安全和未成年人风险是什么？
8. 部署、监控、备份、回退和维护 Owner 是谁？
9. 哪些事实仍未知，最迟在哪个里程碑决策？

未回答这些问题不得复制 Skin 项目结构并宣称完成架构设计。

## 生命周期

1. 以 Foundation 为主工作流，将项目以 `proposed` 写入注册表。
2. 通过新 ADR 决定所有权、边界、可见性和许可后改为 `approved`。
3. 创建独立仓库及 README、AGENTS、LICENSE、状态页、开发计划和验收命令。
4. 验证通过后改为 `active`；只有 `active` 项目可以成为工作流主仓库。
5. 停止开发时先形成迁移和归档 ADR，再改为 `retired`。
