# 部署架构总览

本文件定义所有环境都要保持的部署性质；正式腾讯云主机、域名、备份、监控和秘密引用的细节由私有 `mc-plan-ops` 拥有。公开应用仓库只提供不含官方环境信息的 Dockerfile 和自部署示例。

## 首发原则

- Linux x86_64、Docker Compose v2、Nginx 反向代理、PostgreSQL、Redis 和腾讯 COS/S3 兼容对象存储。
- 宝塔可以作为 Nginx、证书和主机状态管理界面，但不能成为应用启动、配置或迁移依赖。
- 只有反向代理暴露公网端口；数据库、Redis、管理端口和 worker 只在私有网络可达。
- 各服务使用独立数据库、用户、配置和秘密，即使物理上共用一台主机。
- 应用容器无状态，上传文件不落为本地权威数据，支持以后迁移数据库和增加应用节点。

## 环境层级

- Local：开发者本机与假外部依赖，不使用生产数据。
- Test：自动集成和契约测试，可随时重建。
- Staging：与生产拓扑等价的发布、迁移、备份恢复和安全验证环境。
- Production：受审批、监控、备份、事故响应和最小权限控制。

配置从 Local 到 Production 使用同一键名和不同值。构建产物不因环境重新编译注入秘密；同一不可变镜像经验证后逐级提升。

## 扩容顺序

首发建议至少 8 vCPU、16 GB 内存、100 GB SSD，AI 通过远程 API 调用，无需 GPU。出现真实容量或可用性瓶颈时，依次外置 PostgreSQL/Redis、拆分 worker、增加无状态应用节点和负载均衡，最后才评估 Kubernetes。

## 上线门槛

生产部署前必须具备：健康检查、结构化日志、OpenTelemetry、限流、离机备份、恢复演练、证书与密钥轮换、数据清理任务、监控告警、发布与回退 runbook。任何真实生产配置都不得进入公开仓库。

## 应用运行契约

- liveness 只验证进程自身，不访问远程依赖；readiness 验证必需配置、所属数据库连接和迁移版本，失败时实例不得接流量。
- 健康响应使用稳定状态和组件代号，不返回连接串、issuer 管理地址、异常堆栈、版本漏洞信息或秘密。探针默认仅在私有网络由编排/代理访问。
- 启动时严格验证配置；秘密只通过运行时引用注入。缺少必需值或使用危险默认值必须失败退出，不能静默连入共享或生产资源。
- 应用输出 JSON 日志并初始化 OpenTelemetry；HTTP、队列、outbox 和数据库操作传播 trace/correlation ID。身份、账本、限流和迁移失败使用稳定事件名与指标。
- 应用仓库先给出真实镜像、非 root 用户、端口、探针、迁移和回退命令；Ops 验证这些输入后才创建 Compose/Nginx 或预发布配置。

迁移不由每个应用副本在启动时竞争执行。发布流程先运行受控、向前兼容的迁移，再启动新版本并通过 readiness；Schema 收缩经过观察期。回退仅限仍兼容当前 Schema 的应用版本，身份、账本、审计和撤销状态发生变化后优先前向修复。
