# Skin AI Studio 产品与系统设计

## 用户流程

1. 用户通过对话描述风格、颜色、主题和细节。
2. 系统总结可执行需求并提醒官方免费成品将自动公开。
3. 一个创作会话默认允许三次实际渲染，可由后台配置。
4. 用户预览候选并选择继续调整或确认成品。
5. 确认后生成标准 Java 64×64 PNG，完成结构与内容检查。
6. Official 模式自动发布到 Community；Standalone 模式允许直接下载并可选授权发布。

## 部署模式

| 能力 | `standalone` | `official` |
|---|---|---|
| MC Plan 登录 | 不需要 | 必须 |
| 生成与本地下载 | 支持 | 支持 |
| 模型配置 | 部署者配置 | 平台配置 |
| 社区发布 | 用户 OAuth 授权后可选 | 确认成品后自动 |
| 免费额度/积分 | 部署者策略 | Core 统一策略 |
| 对话保留 | 部署者声明 | 固定执行平台隐私策略 |

两个模式使用同一代码库和配置开关，不维护功能分叉。

## 生成提供商边界

适配器接收结构化创作意图，返回候选文件、模型调用标识、用量和安全结果。业务逻辑不得依赖某厂商特有响应。正式厂商必须通过皮肤有效率、审美质量、编辑一致性、延迟、单次成本、地区可用性、数据使用条款和安全能力基准测试后由 ADR 决定。

## 验证要求

- 文件必须是可解码 PNG，尺寸严格为 64×64。
- 元数据明确 Steve 或 Alex；透明区域和双层布局符合对应模板。
- 保存 SHA-256、字节数和实际媒体类型，拒绝仅靠扩展名判断。
- 生成提示和成品均通过内容安全检查；失败内容不得发布。
- 候选不可通过猜测 URL 访问，二十四小时后自动清理。
