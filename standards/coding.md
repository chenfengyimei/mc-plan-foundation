# 编码标准

## 语言与工具

- 主语言为 TypeScript，包管理器统一使用 `pnpm`。
- 前端采用 Next.js；后端采用 NestJS 模块化单体；持久化使用 PostgreSQL 与 Prisma；异步任务使用 Redis/BullMQ。
- 版本在各仓库脚手架创建时锁定为当时受支持的稳定版本，并提交 lockfile；本标准不固定会过期的具体版本号。

## 结构规则

- 模块按业务能力组织，不按 controller/service 等技术类型建立全局大目录。
- 领域层不直接依赖 Web、队列或数据库框架；外部系统通过端口与适配器隔离。
- 跨仓类型只能从已发布的 Contracts/SDK 导入，禁止复制粘贴。
- 源文件以 300 行为目标；超过 500 行必须拆分或在 PR 中解释。生成文件、迁移、Schema、测试数据和声明式配置例外。
- 函数保持单一职责；复杂分支优先通过领域对象和明确命名拆分，不以“满足行数”为目的机械切割。

## 质量要求

- 开启 TypeScript 严格模式；禁止无说明的 `any`、非空断言和忽略类型错误。
- 输入在边界验证，内部代码使用已验证类型；日志不得包含令牌、密码、邮箱全文或提示词原文。
- 时间保存为 UTC，业务日界线显式指定 `Asia/Shanghai`；禁止依赖服务器本地时区。
- 金额、积分和计数使用整数，不使用浮点数推导账本余额。
- 业务错误使用稳定错误码，不通过错误消息文本驱动客户端逻辑。
