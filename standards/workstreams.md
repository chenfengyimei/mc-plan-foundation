# 主方向与工作流标准

状态：Accepted

适用范围：所有 MC Plan 仓库中的写操作

## 两层方向

- `memory/current/direction.json` 是组合层当前方向，包含里程碑、主要项目、入口门槛和退出条件。
- 每个写工作流有且只有一个主仓库，最多两个可写辅助仓库。
- 只读参考仓库不限数量，不获得写权限，也不参与锁冲突。
- Foundation 中该工作流自己的活动、检查点、交接和完成记录属于协调写入；修改其他 Foundation 内容必须显式锁定 Foundation。

## 开始条件

写入前必须：

1. 分配 `MCP-<里程碑>-<主项目>-<序号>` Tracking ID。
2. 在 `memory/workstreams/active/` 创建符合 v1 结构的记录并提交。
3. 确认主仓库属于当前方向的主要或允许辅助项目；否则记录获准的方向例外。
4. 对每个可写仓库记录干净的起始提交，创建包含 Tracking ID 的短期分支。
5. 运行协调预检。失败时不得开始编辑。

方向例外只允许严重安全或数据损失修复、合规纠正和 Foundation 治理维护；必须记录原因和用户授权。

## 锁与范围

主仓库和辅助仓库组成工作流锁。活动工作流锁不得相交，锁永不自动过期。新增可写仓库前必须先更新记录并重新预检；需要三个以上辅助仓库时拆成按契约和部署顺序连接的工作流。

同一工作流中所有可写仓库使用包含相同 Tracking ID 的分支。未声明仓库只允许读取；发现未被任何活动工作流覆盖的改动时停止。

## 检查点与结束

- 每个可审查切片提交后，更新摘要、提交哈希和实际验证结果。
- 被阻塞时记录原因和解除条件；移交时记录来源、接收者、时间、提交和剩余工作。
- 接管必须追加交接历史，不能覆盖原 Owner 或靠超时自动解锁。
- 完成记录必须包含验收证据、验证结果和每个可写仓库的最终提交；随后移动到 `completed/`。
- 组合里程碑变化才更新 portfolio；单仓里程碑变化才更新该仓库状态页。

## 本地与远程阶段

远程仓库建立前，活动记录和检查点使用 Foundation 本地 Git 小步提交。远程建立后，Issue/PR 保存讨论和审查细节，Foundation 只保留方向、范围、依赖、交接和里程碑事实。
