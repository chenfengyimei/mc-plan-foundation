# ADR-0013：F1 预发布基线采用本地记录形态

状态：Accepted
日期：2026-10-09

## 背景

F1 的"预发布"门槛原先被理解为需要生产域名（Q-004）、生产邮件服务（Q-006）、托管数据层（Q-014）、生产监控与告警产品（Q-015）与正式 RPO/RTO（Q-016）的采购决策。这些决策在 `memory/open-questions.md` 中均属 V1/公开测试前的所有者门槛，且在 F1 期间没有任何一条到达必须决策的位置——按表内门槛规则，实现者不得写入临时默认值。

项目所有者于 2026-10-08 会话内明确决策：**预发布基线 = 本地记录**；同批决策 Q-015 = 本地有界指标面（不选择生产监控提供商）。本地证据链已经真实存在并通过验收：

- 真实 Keycloak 26.8 身份/邮件/密码恢复链路（`MCP-F1-OPS-001`/`MCP-F1-OPS-002`，Mailpit 收信，非生产邮件）；
- 双专属 project 备份-破坏-恢复演练（`MCP-F1-OPS-003`）：实测 RPO 5.0/5.2 秒、RTO 12.8 秒、恢复后迁移不重放、账本触发器经恢复仍拒改写、事件不漏投不重投——实测值只作本地证据，不构成正式目标；
- 本地有界指标面（`MCP-F1-CORE-011`，Q-015）：OTEL_ENABLED 时本地 Prometheus 拉取端口真实导出 outbox 与事件投递指标，无生产监控/告警选择。

## 决策

F1 的预发布基线以**本地记录形态**成立，不进行任何生产采购：

- **本地运行基线**：单机 Docker Compose（Keycloak + PostgreSQL + Core + Mailpit），全部验收以本机真实容器执行并留证；不申请备案域名、不选择云地域、不采购生产邮件/托管数据层/监控产品。
- **Q-015 已决为本地有界**：指标面只做进程内 Prometheus 拉取（`OTEL_METRICS_PORT`），告警与生产监控产品保持未决；升级须新决策。
- **Q-004/Q-006/Q-014/Q-016 决策顺延**：这四项按 `memory/open-questions.md` 原有门槛移至 V1 真实部署/公开测试前，不在 F1 内决策，也不因本 ADR 被视为已决。
- **实测值不升格**：恢复演练的 RPO/RTO 实测值与一切本地验收数字只作为 F1 的本地证据，不写成生产 SLA 或正式 RPO/RTO 目标。

## 后果

- F1 出口以本地证据集衡量（身份/资料/权益/积分/审计/outbox/事件投递/注销的完整闭环 + 恢复演练 + 本地指标面），不再等待生产采购。
- V1 进入真实生产环境前，Q-004（备案域名/地域）、Q-006（生产邮件）、Q-014（托管数据层）、Q-016（正式 RPO/RTO）与监控/告警选择必须按各自门槛重新决策；届时本基线不构成约束。
- 任何会话不得把"本地记录基线"用作跳过真实验收的理由；本地验收的全部真实性标准（真实容器、真实令牌、诚实标注合成夹具）不变。

## 变更条件

进入真实生产/备案域名环境、或所有者要求公开测试时，重开本决策并按 `memory/open-questions.md` 的门槛逐项决策；在此之前不得提前采购或写入生产默认值。
